# Blogging Platform API

A REST API for a personal blogging platform. It supports full CRUD on blog posts plus a search filter, backed by PostgreSQL.

This is my implementation of the [Blogging Platform API project](https://roadmap.sh/projects/blogging-platform-api) from [roadmap.sh](https://roadmap.sh).

## What it does

- Create, read, update, and delete blog posts
- Search posts by keyword across title, content, and category (case-insensitive)
- Validates incoming request bodies and returns clear 400 errors instead of crashing
- Returns the correct HTTP status code for every case (201, 200, 204, 400, 404)
- Stores everything in PostgreSQL, so data survives a server restart

There is no authentication. The project spec doesn't call for it, so every endpoint is public.

## API

Base URL when running locally: `http://localhost:3000`

### Post shape

```json
{
  "id": "cead931b-e0a0-4490-ae77-758f74f3966b",
  "title": "My First Post",
  "content": "Hello world",
  "category": "general",
  "tags": ["intro", "writing"],
  "createdAt": "2026-08-29T20:08:58.291Z",
  "updatedAt": "2026-08-29T20:08:58.291Z"
}
```

`id`, `createdAt`, and `updatedAt` are generated by the database. You only send `title`, `content`, `category`, and optionally `tags`.

### Endpoints

| Method | Endpoint | What it does | Success | Errors |
|---|---|---|---|---|
| GET | `/health` | Health check | 200 | — |
| POST | `/posts` | Create a post | 201 | 400 |
| GET | `/posts` | Get all posts | 200 | — |
| GET | `/posts?term=keyword` | Search posts | 200 | — |
| GET | `/posts/:id` | Get one post | 200 | 404 |
| PUT | `/posts/:id` | Update a post | 200 | 400, 404 |
| DELETE | `/posts/:id` | Delete a post | 204 | 404 |

### Notes on behavior

**Creating a post.** `title`, `content`, and `category` are all required and can't be empty or just whitespace. `tags` is optional, but if you send it, it has to be an array.

```
POST /posts
{
  "title": "My First Post",
  "content": "Hello world",
  "category": "general",
  "tags": ["intro"]
}
```

**Updating a post.** You only have to send the fields you want to change. Anything you leave out keeps its current value. At least one field is required, so an empty body returns a 400.

```
PUT /posts/:id
{
  "title": "Updated Title"
}
```

**Search.** `GET /posts?term=node` looks for the term anywhere in the title, content, or category. It ignores capitalization, so `node`, `Node`, and `NODE` all return the same results. The filtering happens in the database rather than in application code.

**Errors.** Every error response uses the same shape so a client only has to handle one format:

```json
{ "error": "Post not found" }
```

Validation errors include a `details` array with the specific problems:

```json
{
  "error": "Validation failed",
  "details": [
    { "msg": "Title is required", "path": "title" }
  ]
}
```

## Setup

### Requirements

- Node.js 20.19 or newer
- PostgreSQL 17

### 1. Clone and install

```bash
git clone https://github.com/tuanhoang0117/Blogging-Platform-API-.git
cd Blogging-Platform-API-
npm install
```

### 2. Create the databases

You need two: one for development and one for tests. The test database gets wiped between test runs, which is why it's kept separate.

```bash
createdb blogging_platform
createdb blogging_platform_test
```

### 3. Set up environment files

Copy the example files and replace `YOUR_PG_USER` with your Postgres username.

```bash
cp .env.example .env
cp .env.test.example .env.test
```

If you installed Postgres with Homebrew, your username is usually your Mac account name. You can check with `psql -c "SELECT current_user;"`.

### 4. Create the tables

```bash
npx prisma migrate deploy
npx prisma generate
```

Then do the same for the test database:

```bash
DATABASE_URL="postgresql://YOUR_PG_USER@localhost:5432/blogging_platform_test?schema=public" npx prisma migrate deploy
```

### 5. Run it

```bash
npm run dev
```

The server starts on port 3000. Check that it's up:

```bash
curl http://localhost:3000/health
```

You should get `{"status":"ok"}`.

## Testing

```bash
npm test
```

This runs against the test database, not your development one, so it won't touch your data. Tests cover the health check, listing posts, creating a post, and validation failures.

### Testing by hand

If you want to hit the endpoints yourself, here are curl commands for each one. Postman works the same way.

Create a post:

```bash
curl -X POST http://localhost:3000/posts \
  -H "Content-Type: application/json" \
  -d '{"title":"First Post","content":"Hello world","category":"general","tags":["intro"]}'
```

Copy the `id` from the response, then:

```bash
# get all posts
curl http://localhost:3000/posts

# search
curl "http://localhost:3000/posts?term=hello"

# get one post
curl http://localhost:3000/posts/PASTE_ID_HERE

# update just the title
curl -X PUT http://localhost:3000/posts/PASTE_ID_HERE \
  -H "Content-Type: application/json" \
  -d '{"title":"Updated Title"}'

# delete it
curl -X DELETE http://localhost:3000/posts/PASTE_ID_HERE
```

## Project structure

```
src/
  app.js          Express app, all routes and middleware
  server.js       Starts the server (kept separate so tests can import the app)
  prisma.js       Database client, created once and shared
  app.test.js     Tests
prisma/
  schema.prisma   Database schema
  migrations/     Migration history
```

`app.js` and `server.js` are split so the tests can import the app without starting a server on a real port.
